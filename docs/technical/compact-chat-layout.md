# Compact mobile layout and task conversation

Desktop tab navigation is rendered inside the task header through its children slot; the reference-PR header likewise contains its tab list. Both headers sit within the library Tabs context, align navigation with header content and own the bottom divider. Mobile keeps its separate pill navigation.

Selected desktop triggers have a subtle primary top/side border and a stronger bottom underline. Keyboard focus uses an inset ring with no outer offset, keeping it visible inside the horizontally scrolling tab row; the native outline is suppressed. Mobile pills are unchanged.

Desktop task-detail and reference-PR tabs share `task-detail-tabs.css`: compact underline triggers with rounded top corners only, no tab-list or vertical trigger padding, a subtle primary selected surface, neutral hover, compact library Badge counters and an accessible keyboard-focus ring. The desktop tab row shares the header background without an intervening border, gap or separate framed surface; only the divider below the navigation remains. Library Tabs retain their keyboard behavior; the tab row scrolls horizontally within its own width when necessary. Mobile retains its existing pill tab navigation.

Comments separate consecutive calendar days with the UI library's `FieldSeparator`. The current day is labelled Today / Hôm nay; other days use the selected locale's medium date format. Grouping uses the viewer's local calendar and preserves API order. SAP wall timestamps are parsed as local time; timestamps with offsets represent instants in the viewer's timezone. Missing/invalid dates form an Unknown date / Không rõ ngày group and never default to today. `commentTimeline.ts` isolates parsing and grouping from rendering; styles stay in `task-chat.css`. `useCommentToday` refreshes the relative day label at local midnight and when the tab regains focus or becomes visible, clearing its timer/listeners on unmount.

Timeline regression coverage includes same-day messages, day transitions, offset timestamps around midnight, invalid/missing dates, desktop/mobile separators, Vietnamese copy, own-message alignment, and profile identity sharing. Tests use fixtures rather than live SAP.

Profile and Comments share `useUserIdentity`. When the SAP principal is not already known, the lazy `GET /tasks/me/sap-user` endpoint reads `/sap/bc/ui2/start_up` through the existing SapClient and the caller's JWT/destination. Its `id` is the SAP session username after Principal Propagation; it is not inferred from IAS email or the business-user directory. The frontend reuses this account-scoped result for the session. Login names remain immediately available through `/me`. Cloud Connector must expose the read-only SAP startup endpoint; failures produce 502 and Profile offers retry. The field uses library Field components and SAP 72 through the shared font token.

Comments display the persisted SAP author ID and its initials. Own comments align right when that ID matches the resolved SAP session user, ignoring case and surrounding whitespace. Unresolved identities retain the author ID and stay left instead of displaying a guessed person. No business-user directory request is needed for Comments or Profile; directory search remains available for mentions and user pickers.

Only verified `sapUsername` or the server's explicit local `commentAuthorId` establishes SAP ownership. General IAS login IDs, non-email usernames, email addresses and display names never skip SAP session resolution or establish ownership. Obsolete directory/name-mapping helpers have been removed. Browser regressions include a non-email IAS username that matches another comment author, midnight rollover, and focus after backgrounding.

Frontend `npm run typecheck` now checks `tsconfig.app.json` directly. Detail types include the raw envelope/legacy summary fields consumed by current renderers, retain legacy SAP property casing, and keep workflow requester metadata in the normalized task. Invalid optional headers are guarded before object spread. Null detail rendering is guarded, the mobile tab gesture hook receives the actual DOM ref object, and the synchronous tag picker no longer references submission state or resets selection because of an unstable default array.

The conversation now uses the UI library Card with the same rounded corners, subtle border, and shadow as the other detail panels. Its host preserves the existing desktop/mobile tab padding rather than overriding it with zero padding. History scrolls inside the card and the composer stays docked within it; the composer retains its compact desktop width.

QAS configuration was inspected read-only: the SAP destination uses PrincipalPropagation. Email-to-directory matching cannot guarantee the SAP principal in that setup. Live identity endpoint validation still requires the user's deployed authenticated session; no deployment or build was performed during this change.

The desktop sidebar uses compact navigation rows with a translucent primary background and primary text for the selected route, without a left accent. Navigation lives in `AppSidebarNavigation`, uses UI-library menu buttons and collapsed-state tooltips, and exposes `aria-current` for the active route. Administration is separated from the main links. The circular collapse/expand control floats on the upper outer edge, retaining the original placement. Expanded and collapsed layouts share `app-sidebar.css`; mobile continues to use its bottom navigation, and Work Zone keeps ownership of its branding and account controls.

Collapsed navigation retains the same `h-9` row height, `size-5` icons, and vertical spacing as expanded navigation. A scoped override counters the UI library's important `size-8` collapse rule, which otherwise shortens each row and shifts the icon positions upward.

The application shell sets collapsed sidebar width from the shared spacing scale (`16` units), overriding the provider's narrower inherited default. Both the fixed sidebar and its content spacer read the same variable. Collapsed menu buttons fill the available width and center their unchanged icons; the account avatar and logo remain centered as well.

All account, profile, conversation, mention, tagging, and forwarding avatars use the shared `UserAvatar` component, composed from the UI library avatar with neutral foreground/background theme tokens.

Mobile Home retains its branded header with the welcome message, pending approval summary, and compact account menu. This header is scoped to Home; other mobile pages retain their compact toolbars.

The desktop composer has no surrounding surface or full-width divider; only the centered input shell is visible. The mobile composer retains its existing surface and divider.

After a successful comment POST, the mutation awaits a single invalidation/refetch of the active task before reporting success and clearing the draft. The pending skeleton and editor lock remain through this read. Workflow invalidation runs separately. The detail view does not trigger a second refresh; this prevents cancellation/restart of the in-flight task read. Regression checks hold the task GET after a successful POST and verify that no success toast appears before the refreshed message on mobile and desktop.

Comments uses the existing panel and RichMentionInput. It fills the detail pane on mobile and desktop, without a second card header or nested page padding. Message history owns scrolling and the composer stays at the bottom. Parent pull-to-refresh and next-tab gestures are disabled while the conversation is active so scrolling history does not switch tabs. Reference PR conversations use the same layout in read-only mode.

Local mock sessions using explicit direct Basic Auth expose the configured writer separately through `/me`; this fallback is disabled for JWT sessions, production, Cloud Foundry, destinations, or user-header forwarding. SAP identity resolution does not block application startup or change authentication. Mentions, forwarding context, timestamps, mutation invalidation, and read-only permissions remain available. Failed submissions keep the draft; pending submissions cannot be sent again.

The conversation uses neutral outlined avatars and subtle bordered message bubbles. Author and compact timestamp share a metadata row. The composer is a single input shell with a send button; typing `@` opens mentions without a separate mention button or help row. During submission, a right-aligned message skeleton appears, the editor becomes noneditable, and a synchronous guard prevents duplicate submission. Identity comparison trims whitespace and ignores case; normalization preserves the persisted author ID separately from the display name.

Long bubbles have a readable desktop width and wrap unbroken content within the available mobile width. The composer grows only up to the shared `max-h-24` scale and then scrolls internally, with its send button outside that scrolling area. Browser-created block lines and blank lines are preserved when serializing rich text for submission.

On mobile, the composer places the full-width editor above a compact footer with an always-visible `count/255` counter and send action. At the desktop breakpoint, the input shell is centered with the shared `max-w-3xl` width, and the editor, counter, and smaller send button share one row with reduced padding. Multiline drafts still grow to the same bounded height. Counting uses the exact trimmed payload sent to the API, including mention markup and line breaks, with JavaScript string length to match backend validation. Drafts above 255 characters remain editable and show a localized error; both button submission and Ctrl/Cmd+Enter are blocked. The counter resets after success, while failures retain the draft. The textbox exposes its invalid state and describes the counter/error for assistive technology.

AccountMenu uses the UI library dropdown and avatar. Mobile Inbox places it beside search, Home beside the greeting, and Dashboard beside the page title. Desktop sidebar provides direct logout plus access to the existing profile dialog, including its administrative action. Work Zone owns its account controls. Header and chat styles use theme tokens and the shared spacing scale; copy lives in en/vi locales.

Validation uses the Vite development server with API fixtures (no production build): iPhone and Android viewports plus desktop; full TaskDetailView sizing, email-to-SAP ownership with different login IDs, multiline and blank-line serialization, long unbroken drafts with bounded height and no horizontal overflow, mention serialization and tagged users, successful send, retained failed draft, keyboard submission, read-only mode, and account menu. Device keyboard behavior and physical iOS installation still require device verification.

# Swagger / OpenAPI Reference

> **Owner:** Project Team | **Last Updated:** 2026-10-20 | **Status:** Active

Swagger UI is implemented at `/api/cnma/APPROVAL_SRV/api-docs` by [server.ts](../../../srv/server.ts).
This file keeps its previous filename to preserve inbound links; it is no longer a placeholder.

## Source and deployment

OpenAPI 3.0 is generated by `swagger-jsdoc` from controller and server annotations.
Annotation paths are resolved relative to the executing server directory, covering local TypeScript and compiled JavaScript in the deployed `gen/srv` package.
The OpenAPI server URL is `/api/cnma/APPROVAL_SRV`, relative to the current host; it contains no SAP backend host.

The REST router is mounted at `/tasks`. For example, task detail is `/tasks/{id}`, not `/tasks/{id}`.
All mounted REST operations are covered, including health, deprecated debug-config, identity, counts, reference PR, attachment variants and notification administration.
There is no mounted attachment-upload REST endpoint.

## Authentication and response contracts

Use the Bearer authorization control for authenticated requests. Local auth and actual production middleware conditions are described in [security architecture](../01-architecture/02-auth-security.md).
Swagger UI and health/debug-config are mounted before the custom task JWT middleware. No dev-only Swagger gate currently exists in the server.

Raw SAP objects vary by document type. Schemas keep unmodeled response fields open instead of inventing a canonical DTO.
Action bodies document decision-key alternatives, comment context and mentions, forwarding, bulk items and notification inputs.
CAP OData actions in `service.cds` are separate from this custom REST specification; see the [API reference](../02-implementation/03-backend-bff-endpoints.md).

## Verification

```powershell
npx.cmd vitest run tests/unit/documentation/openapi.test.ts
```

The tests parse annotations with `failOnErrors`, compare documented operations against mounted router/server routes, expand optional filename variants, and verify required path parameters.
No live approval, forwarding, notification or SAP connectivity operation is executed by this validation.

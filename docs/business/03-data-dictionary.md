# Business Data Dictionary

> **Owner:** Lead Business Analyst | **Last Updated:** 2026-08-17 | **Status:** Active

This data dictionary defines key procurement, financial, and inventory concepts used throughout the **CNMA Approval** portal. These fields map directly to information imported from S/4HANA ERP records.

---

## 📦 Purchase Requisitions (PR)
A **Purchase Requisition** is an internal request created by an employee or department to authorize the purchase of goods or services.

### Document Subtypes
*   **Asset Requisition (ZASS)**: Requisition for fixed assets requiring capital expenditure tracking, asset numbers, and investment profile assignments.
*   **Asset Subcontracting Requisition (ZMAK)**: Requisition combining asset investment with external subcontracting services.
*   **Standard Purchase Requisition (ZNB1)**: General stock or non-stock procurement requisition for standard operational requirements.
*   **Service Purchase Requisition (ZNB2)**: Requisition for external services, consulting, or maintenance work orders with service item breakdowns.
*   **Toll Manufacturing Requisition (ZTOL)**: Requisition for third-party tolling/processing services where raw materials are provided to a vendor.
*   **Expense Requisition (ZEXP)**: Direct operational expense requisition charged to departmental cost centers.

### Header Fields
*   **Requisition Number**: Unique identification number generated by the ERP.
*   **Document Type**: Code specifying the requisition type and subtype (e.g., ZASS, ZMAK, ZNB1, ZNB2, ZTOL, ZEXP).
*   **Total Net Amount**: Total estimated value of the requisition converted to local currency (VND).
*   **Document Currency**: The original currency in which the requisition was created (e.g., USD, EUR, VND).
*   **Requester Name**: Employee or system account that submitted the requisition (resolved in order of Username, User Full Name, or Created By User ID).
*   **Department / Plant**: Originating organizational unit requesting the procurement.
*   **Created On**: Date and time the requisition was registered.
*   **Priority**: Criticality indicator (Low, Medium, High, Very High) determining review urgency.

### Line Item Fields
*   **Item Number**: Sequential line number (e.g., 00010, 00020).
*   **Material Description**: Name and description of the requested goods or services.
*   **Quantity**: Number of units requested.
*   **Unit of Measure**: Standard measurement unit (e.g., PC for pieces, EA for each, HUR for hours).
*   **Net Price**: Unit price of the item in original currency.
*   **Net Value**: Total calculated value of the line item (Quantity x Net Price).

## 💼 Purchase Orders (PO)
A **Purchase Order** is a legally binding contract sent to a supplier, committing to purchase items under negotiated prices, terms, and delivery schedules.

### Document Subtypes
*   **Asset Purchase Order (ZASS)**: Contract for purchasing fixed asset machinery, equipment, or facility upgrades.
*   **Consignment Purchase Order (ZCON)**: Order for goods stored at purchaser premises but owned by vendor until consumed.
*   **Subcontracting Purchase Order (ZCOR)**: Contract for external processing where materials are supplied to the vendor.
*   **Asset Subcontracting Purchase Order (ZMAK)**: Contract combining asset creation with third-party processing.
*   **Standard Purchase Order (ZNB1)**: Regular procurement contract for materials or inventory.
*   **Service Purchase Order (ZNB2)**: Contract for service execution and labor deliverables.
*   **Return Purchase Order (ZNBR)**: Contract managing return of goods or credit notes to suppliers.
*   **Toll Processing Purchase Order (ZTOL)**: Contract for toll manufacturing services.
*   **Stock Transfer Purchase Order (ZUB)**: Internal transfer order moving goods between company plants or storage locations.

### Header Fields
*   **Order Number**: Unique identification number representing the contract.
*   **Supplier / Vendor**: The vendor supplying the goods or services.
*   **Company Code**: The legal entity code of the purchasing enterprise.
*   **Purchasing Organization**: The procurement department responsible for negotiating terms.
*   **Payment Terms**: Agreed terms outlining when payment is due (e.g., Net 30 days).
*   **Order Value**: The total contractual value of the purchase order.

### Line Item & Account Assignment Fields
*   **Material Number / Description**: Catalog ID and description of the material being purchased.
*   **Plant**: The destination facility or plant where goods will be delivered.
*   **Storage Location**: Internal warehouse area designated for receipt.
*   **G/L Account**: General Ledger chart of accounts code for financial reporting.
*   **Cost Center**: The department budget to which the expense is charged.
*   **Reference Purchase Requisition**: Originating Purchase Requisition document number and item number that requested the procurement. Approvers can inspect the referenced PR details directly from the purchase order item.

### Header & Timeline Notes
*   **Document Notes & Comments**: Historical collaboration notes written by approvers during the workflow lifecycle, synchronized directly with ERP header text notes.

## 🔁 Workflow Approval Steps
Each procurement request follows a predefined multi-tier release strategy:
*   **Step Level**: Numerical position in the approval sequence (e.g., Level 1, Level 2).
*   **Release Code**: SAP approval role code authorizing the release.
*   **Release Step Title / Description**: Descriptive label for the approval stage (e.g., Department Manager Approval, Finance Review, Executive Sign-off).
*   **Approver Name & User ID**: Assigned approver responsible for reviewing the request.
*   **Decision Status**: Current state of approval (Pending, Approved, Rejected).

## 💳 Expense Claims (CLAIM)
An **Expense Claim** is an employee financial reimbursement request for business-related expenditures (e.g., travel expenses, client entertainment, training).

### Header Fields
*   **Claim Number**: Unique identifier assigned to the reimbursement claim.
*   **Claimant Name**: Employee requesting reimbursement.
*   **Claim Category**: Classification of expenses (Travel, Training, Entertainment, Supplies).
*   **Total Amount**: Aggregated sum of all requested expenses.
*   **Currency**: Reimbursement currency.
*   **Submission Date**: Date the claim was submitted for approval.

### Line Item Fields
*   **Expense Description**: Plain text description of the individual expenditure.
*   **Expense Date**: Date the expense occurred.
*   **Amount**: Value of the individual receipt or invoice.
*   **Tax Code / VAT**: Tax applicability indicator.
*   **Receipt Attached**: Indicator confirming whether a receipt proof was attached.

## 🧱 Material Reservations (RE)
A **Material Reservation** is an internal inventory request to reserve warehouse stock for a specific project, maintenance order, or cost center before physical withdrawal.

### Header Fields
*   **Reservation Number**: Unique inventory reservation document number.
*   **Movement Type**: SAP inventory movement code indicating the withdrawal purpose (e.g., 201 for Cost Center consumption).
*   **Base Location / Plant**: Storage plant issuing the material.
*   **Required Date**: Target date by which the material must be staged or issued.
*   **Cost Center / Order**: Project or department to which inventory costs will be posted.

### Line Item Fields
*   **Item Number**: Line number of the reserved item.
*   **Material Code & Description**: Inventory code and description.
*   **Quantity Reserved**: Quantity set aside in stock.
*   **Unit of Issue**: Warehouse unit of measurement.

## 👥 Business Users & Collaboration Entities (`CNMA_BUSUSER`)

The collaboration sub-system references the SAP business users directory for tagging and task forwarding:

### User Directory Fields (`CNMA_BUSUSER`)
*   **SAPUserName**: Unique SAP user ID / login name (e.g. `MINHDT`, `DUNGNV`).
*   **FullName**: Complete display name of the user (e.g. `Do Tu Minh`).
*   **FirstName**: User's given name.
*   **LastName**: User's surname / family name.
*   **EmailAddress**: Primary corporate email address for workflow and CC notifications.

### Task Forwarding Parameters
*   **instanceId**: SAP Task Gateway workflow task instance identifier.
*   **forwardTo**: Target SAP user ID to whom task ownership and release authorization is delegated.
*   **comment**: Reason or instruction note recorded by the original approver when delegating the task. Automatically pushed as an ERP document note (`[Forwarded to ${forwardTo}] ${comment}`).
